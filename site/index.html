Mini-SIEM

J'ai voulu savoir si on peut repérer des attaques web juste en lisant les logs d'un serveur. J'ai donc monté un petit labo, généré du trafic normal et des attaques, puis construit la chaîne complète : ETL, entrepôt de données, règles de détection testées, API et tableau de bord.

Voir le code sur GitHub Rapport d'une page (PDF)

Projet éducatif : tout a tourné en local sur mon PC, contre une application volontairement vulnérable (OWASP Juice Shop). Aucune cible réelle n'a été attaquée. Cette page est une vitrine statique : elle montre un instantané des résultats, sans aucun serveur derrière.

La démo en une minute

Comment ça marche

  1. Le laboJuice Shop derrière nginx, dans Docker. nginx écrit une ligne par requête dans access.log. Tout est lié à 127.0.0.1.
  2. Le traficattack_sim.py envoie 200 visites normales et 5 attaques : brute force, injection SQL, XSS, scan de pages, remontée de dossiers. Il refuse toute cible qui n'est pas localhost.
  3. L'ETLPython et pandas lisent le journal avec une regex, décodent les URL (%27 devient ') et chargent PostgreSQL : une zone staging, puis un schéma en étoile.
  4. La détection5 règles, par comptage (trop de 401 ou de 404 par IP et par minute) ou par motif dans l'URL. 30 tests pytest.
  5. La restitutionUne API FastAPI aux requêtes SQL paramétrées, et un dashboard Streamlit. Ci-dessous, le même dashboard en version statique.

Chaque règle a ses tests : une ligne de log qui doit déclencher l'alerte, une ligne normale qui ne doit pas, et les seuils testés pile à la limite (10 échecs : rien ; 11 : alerte).

Ce que j'en retiens

  • Un log ne voit pas tout. nginx n'écrit pas le corps des requêtes POST : une injection envoyée dans un formulaire est invisible.
  • Une IP, ça se falsifie. Ici les IP viennent de l'en-tête X-Forwarded-For, pratique en labo, mais à ne croire que d'un proxy connu en production.
  • Les faux positifs existent. Chercher « l'orange » ressemble à une injection SQL à cause de l'apostrophe : 36 alertes de ce type, que j'ai classées en gravité faible plutôt que d'ignorer les apostrophes.
  • Compter par minute fixe a un trou. 8 échecs à 16:49:55 puis 8 à 16:50:05 ne déclenchent rien. Une fenêtre glissante de 60 s corrigerait ça.
